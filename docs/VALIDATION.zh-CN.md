## M0：原生前置验收

在 Windows 11 x64、普通用户账户执行。先只读验证系统字体：

```powershell
dotnet run --project tools/FontCrate.Verify -c Release -- "$env:WINDIR\Fonts\arial.ttf"
```

输出每个 face 在 96 / 144 / 192 DPI 的 PNG 及 `verification.json`。检查预览清晰、集合 face 正确，中文和补充平面缺字与实际字体一致。对合法中文 TTF、OTF、TTC 和 OTC 样本分别重复；用于系统操作的样本须支持 Windows GDI。

再使用**尚未安装、没有名称冲突**的测试字体执行完整系统操作：

```powershell
dotnet run --project tools/FontCrate.Verify -c Release -- "D:\FontTests\UninstalledFont.ttf" --exercise
```

`--exercise` 会实际进行临时启用、当前用户安装和卸载。程序检查 GDI 新增枚举项、DirectWrite 系统集合中的实际文件、安装交接和退出后持久字体状态；正常结束时卸载测试字体。它不修改输入文件，不卸载已有字体。

如果清理失败，程序会保留并输出验证数据目录。关闭占用字体的软件后，在同一 Windows 用户账户重试：

```powershell
dotnet run --project tools/FontCrate.Verify -c Release -- --recover "C:\Users\USER\AppData\Local\Temp\fontlite-verify-..."
```

此命令只核对该验证数据库记录的操作，并卸载该验证工具持有的测试字体。原生前置验收全部通过后，才能把 M0 标记完成。

## 性能验收

基准机器：Windows 11 x64、4 核 CPU、16 GB RAM、SSD。样本包含 1 万个真实 face，记录文件数、总字节数、集合数量、中文和变量字体比例。

| 指标 | 目标 |
|---|---|
| 已建库启动至显示首批数据并可操作 | ≤ 3 秒 |
| 搜索至结果展示 p95，不含 200ms 防抖 | ≤ 300ms |
| 首次选中字体至预览展示 p95，不含输入防抖 | ≤ 500ms |
| 空闲私有内存 | ≤ 200 MiB |
| 扫描峰值私有内存 | ≤ 400 MiB |

应用在 `%LOCALAPPDATA%\FontCrate\performance.jsonl` 记录启动、查询、预览和扫描时间；日志轮转上限约 1 MiB。正式计时前明确使用当前日志时间窗口，避免混入之前的样本。

启动应用并执行扫描/搜索/预览时，在第二个 PowerShell 窗口运行：

```powershell
powershell -ExecutionPolicy Bypass -File tools/measure.ps1 -Seconds 120
```

输出私有内存、工作集采样和各操作 p95。分别采集启动、空闲、首次扫描、增量重扫、校验重扫和连续预览场景。扫描是否保持界面响应还需人工验证。

Windows 手动验收（当前 Linux 环境无法替代）：

1. 浅色/深色及 100%/150%/200% DPI：宽窗口双栏，窄窗口上下排列；长路径和分类名称不覆盖操作，滚动可访问全部内容。
2. 来源空列表、搜索无匹配、离线目录：统计和提示正确；打开目录失败有反馈；扫描所选来源不扫描其他来源。
3. 标签/合集反复切换与离开返回：搜索、选择和滚动保留，不修改字体库原筛选；只有“在字体库查看”应用目标来源或分类。
4. 新建/改名：空白、超长、重名时原生弹窗保持打开并显示错误；取消、Esc、窗口隐藏均不保存。
5. 添加字体：已关联项不出现，空选择不能提交；取消不修改，重复提交不产生重复关联；移除多选关联和删除分类只影响目标分类。
6. 大量字体快速搜索、切换分类和滚动：旧查询不能覆盖新详情，只生成可见行的缩略图；离线字体可移除关联，但不能预览。
7. 操作中关闭/托盘退出：等待已开始的管理提交与字体任务收尾，继续执行临时字体清理。
